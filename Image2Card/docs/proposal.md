
# 项目 Proposal：基于视觉语言模型的图片知识卡片管理系统

## 1. 项目名称

**Image2Card：基于图片的个人知识卡片管理系统**

备选名称：

- 图识卡片
- 拍照知识库
- SnapKnow
- 视觉知识卡片库
- Image-based Knowledge Card Manager

---

## 2. 项目背景与痛点

在日常生活和学习中，用户经常会遇到一张信息密度很高的图片，例如：

- 出国旅游时看到一张外语菜单；
- 阅读教材、讲义、论文截图时遇到大量陌生术语；
- 学习哲学、历史、数学、计算机等课程时，一页纸上出现许多概念、人名、公式或专有名词；
- 参观博物馆、展览或阅读说明牌时，希望快速理解其中的关键信息。

目前大模型已经可以直接识别图片并解释内容，但这种方式通常是**一次性问答**，缺乏长期状态管理。用户仍然需要手动记录：

- 哪些词已经见过；
- 哪些词自己已经熟悉；
- 哪些词需要复习；
- 某个词最早来自哪张图片；
- 不同知识点之间有什么关系；
- 模型解释和自己的理解如何分开保存。

因此，本项目希望解决的问题是：

> 当用户面对一张充满陌生概念的图片时，只需要上传图片，系统就能自动识别值得学习的词条，并将其转化为可编辑、可管理、可复习、可关联的知识卡片。

---

## 3. 项目目标

本项目拟实现一个桌面端GUI应用，用户可以上传图片，系统调用可配置的视觉语言模型，对图片内容进行理解，识别出适合制作知识卡片的术语、概念、实体或公式，并生成结构化候选卡片。用户确认后，这些候选卡片会进入个人知识库。

系统不仅关注“识别图片”，更关注**图片识别后的知识状态管理**。

核心目标包括：

1. 将图片中的陌生知识点自动转化为候选卡片；
2. 支持用户确认、忽略、合并和编辑候选卡片；
3. 建立长期个人词条库，记录熟悉度、笔记、链接和来源图片；
4. 支持卡片之间的关系维护，形成轻量知识图谱；
5. 提供复习模式，帮助用户根据熟悉度巩固知识；
6. 支持用户自定义视觉语言模型识别器，包括模型接口、Prompt 模板和识别场景。

---

## 4. 项目核心特点

### 4.1 基于图片的知识库

传统笔记软件通常要求用户手动输入知识点。本项目以图片作为知识入口，用户上传一张图片后，系统自动分析其中的高价值知识点，并生成卡片。

图片可以是：

- 菜单照片；
- 教材截图；
- 数学作业；
- 论文页面；
- 博物馆展板；
- 课堂板书；
- 讲义或 PPT 页面。

每张卡片都会记录来源图片，因此用户既可以从图片回到卡片，也可以从卡片回到原始语境。

---

### 4.2 视觉语言模型驱动的知识抽取

本项目不采用传统的 “OCR + 分词 + 命名实体识别” 流程，而是直接使用视觉语言模型完成图片理解。

系统要求模型返回结构化结果，例如：

- 图片场景；
- 图片语言；
- 候选词条；
- 词条类型；
- 简短解释；
- 推荐理由；
- 互联网链接；
- 与其他词条的关系；
- 图片中的位置区域。

这样可以避免传统 OCR 在复杂排版、多语言、手写、公式、菜单等场景下不稳定的问题。

---

### 4.3 用户知识状态参与识别

系统不是每次都盲目生成卡片，而是会参考用户已有的卡片库。

例如：

- 如果某个词已经存在，则标记为“已有卡片”；
- 如果某个词用户熟悉度很高，则默认不推荐加入；
- 如果模型识别出的词和已有词相似，则提示用户是否合并；
- 如果某个词在多张图片中反复出现，则增强其重要性。

这使系统从“一次性看图解释工具”变成“长期个人知识管理系统”。

---

### 4.4 人机协同的卡片确认流程

模型生成的结果不会直接进入知识库，而是先进入候选区。用户可以对候选卡片执行：

- 确认加入；
- 忽略；
- 标记为熟悉；
- 合并到已有卡片；
- 编辑模型解释；
- 添加个人笔记；
- 修改熟悉度。

这样既保留了模型生成的效率，又避免了模型误识别、重复生成和解释不准确的问题。

---

### 4.5 模型笔记与用户笔记分离

每张卡片包含两类解释：

| 类型 | 来源 | 编辑权限 | 作用 |
|---|---|---|---|
| 用户笔记 | 用户手动输入 | 用户可编辑 | 保存个人理解、记忆方法、课堂补充 |
| 模型笔记 | 视觉语言模型生成 | 用户可编辑，模型不可覆盖用户笔记 | 提供初始解释、背景信息、总结 |

这个设计的核心思想是：

> 模型可以辅助生成知识，但用户始终拥有最终知识库的编辑权。

---

### 4.6 可自定义识别器

系统支持用户自定义视觉语言模型识别模块。用户可以配置：

- API 地址；
- API Key；
- 模型名称；
- Prompt 模板；
- 场景模式；
- 输出 JSON 格式要求。

系统也可以提供预置模板：

| 场景模板 | 识别重点 |
|---|---|
| 旅游菜单 | 菜名、食材、烹饪方式、过敏原、地方特色 |
| 教材讲义 | 概念、定义、人物、流派、术语 |
| 数学作业 | 定理、公式、符号、前置知识点 |
| 论文截图 | 方法名、模型名、指标、数据集、专业术语 |
| 博物馆展板 | 人物、地点、年代、事件、文化背景 |
| 通用模式 | 图片中值得学习或查询的知识点 |

## 5. 用户使用流程

### 5.1 基本流程

```text
上传图片
  ↓
选择识别模式
  ↓
调用视觉语言模型分析图片
  ↓
生成候选卡片
  ↓
系统与已有卡片库比对
  ↓
用户确认、忽略、合并或编辑
  ↓
正式加入知识库
  ↓
后续搜索、查看、复习、建立关系
```

---

### 5.2 示例场景：旅行菜单

用户在国外餐厅拍摄菜单图片。

系统识别出：

- Carbonara；
- Risotto；
- Tiramisu；
- Pecorino Romano；
- Guanciale。

系统发现：

- Tiramisu 用户熟悉度为 5，默认忽略；
- Carbonara 已有卡片，更新来源图片；
- Guanciale 是新词，推荐创建卡片；
- Pecorino Romano 和 Carbonara 有关系，推荐建立关联。

用户确认后，系统生成对应卡片，并在原图上高亮显示这些词条。

---

### 5.3 示例场景：数学作业

用户上传一张数学题图片。

系统识别出：

- Eigenvalue；
- Matrix diagonalization；
- Linear transformation；
- Characteristic polynomial；
- Determinant。

系统为每个概念生成解释，并记录它们来自同一张图片。系统自动建立“共现关系”，并推荐用户复习线性代数相关概念。

## 6.2 视觉语言模型分析模块

### 功能说明

该模块负责调用用户配置的视觉语言模型，对图片进行理解，并返回结构化候选知识点。

### 输入

- 图片文件；
- 用户选择的场景模板；
- 用户已有卡片摘要；
- Prompt 模板；
- 模型配置。

### 输出

结构化分析结果，包括：

- 场景类型；
- 图片摘要；
- 候选卡片列表；
- 每个候选词的位置；
- 简短解释；
- 相关词推荐；
- 推荐互联网链接。

### 模型输出示例

```json
{
  "scene_type": "restaurant_menu",
  "language": "Italian",
  "summary": "This image is a restaurant menu containing Italian pasta dishes and desserts.",
  "items": [

      "term": "Carbonara",
      "type": "dish",

      "why_selected": "It is a common but potentially unfamiliar Italian dish name.",
      "familiarity_suggestion": 2,
      "links": [
        {
          "title": "Wikipedia",
          "url": "https://en.wikipedia.org/wiki/Carbonara"
        }
      ],
      "bbox": {
        "x": 120,
        "y": 240,
        "w": 180,
        "h": 32
      },
      "related_terms": [
        "Guanciale",
        "Pecorino Romano"
      ]
    }
  ]
}
```

### 设计重点

该模块需要处理模型输出不稳定的问题，因此需要：

- JSON 格式校验；
- 缺失字段补全；
- 异常结果提示；
- 模型调用失败时展示错误信息；
- 支持 mock 模式，方便离线演示。

## 6.6 知识图谱模块

### 功能说明

该模块维护卡片之间的关系，帮助用户理解不同知识点之间的联系。

### 关系来源

1. 同一张图片中共同出现；
2. 模型推荐；
3. 用户手动添加；
4. 用户在复习或编辑时建立关系。

### 关系类型

| 类型 | 含义 |
|---|---|
| related_to | 一般相关 |
| appears_with | 在同一张图片中共同出现 |
| is_a | A 是 B 的一种 |
| part_of | A 是 B 的组成部分 |
| contrast_with | A 与 B 对比 |
| prerequisite_of | A 是 B 的前置知识 |

### 主要功能

1. 查看当前卡片相关节点；
2. 添加 / 删除 / 修改关系；
3. 从图片自动生成共现关系；
4. 点击图谱节点跳转卡片详情；
5. **力导向布局自动可视化**（节点位置由算法自动计算，不需手动摆放）；
6. **社区检测自动识别主题簇**（同主题卡片自动聚拢、不同主题自动分离）；
7. **桥接节点识别**（发现连接多个主题的关键概念，辅助学习路径推荐）。

### 核心算法：力导向布局（Fruchterman-Reingold）

随着卡片库规模增长（数百到数千节点），手工或随机布局会迅速变成无法阅读的"意大利面"。本系统实现 **Fruchterman-Reingold 力导向布局算法**，把图谱当作物理系统模拟：

- 每对节点之间存在斥力（类库仑力），防止节点重叠；
- 每条边视为弹簧（类胡克定律），将相关节点互相拉近；
- 引入"温度"参数随迭代衰减，逐步收敛到能量最低的稳定布局。

最终效果：相关节点自然聚拢，无关节点自然散开，边的交叉数最小化。该布局过程在 QGraphicsScene 中以动画形式实时展示，具有较强的视觉表现力。

### 核心算法：社区检测（Louvain）

仅有布局还不够——用户依然看到的是一片散点。系统进一步实现 **Louvain 模块度优化算法**，自动将节点划分到不同的"主题社区"：

- 基于模块度（Modularity）指标：同社区内连接稠密、跨社区连接稀疏；
- 采用两阶段贪心优化：节点局部移动 → 社区合并 → 重复至模块度收敛；
- 在 UI 上对不同社区使用不同颜色 / 区域呈现。

社区检测的派生功能包括：

- **新卡片自动归类**：用户无需手动打标签，新加入的卡片基于关系结构自动归簇；
- **桥接节点高亮**：计算每个节点的中介中心性（betweenness centrality），自动识别连接多个主题的"枢纽概念"；
- **复习模式增强**：可按社区进行专题复习（例如"今日复习：线性代数主题，掌握度 60%"）；
- **学习路径推荐**：基于社区拓扑，推荐"学完 A 主题后可以衔接的 B 主题"。

### GUI 设计示意

```text
+------------------------------------------------------+
|  知识图谱 (3 个主题社区，2 个桥接节点)                |
+------------------------------------------------------+
|                                                      |
|   ┌──意大利菜─┐      ┌──线性代数──┐                  |
|   │ Carbonara │      │ Eigenvalue │                  |
|   │ Guanciale │──★──│ Determinant│                   |
|   │ Pecorino  │  桥接│ Diagonalize│                  |
|   └───────────┘      └────────────┘                  |
|         │                                            |
|         ★ 桥接节点                                   |
|         │                                            |
|   ┌──烹饪术语─┐                                      |
|   │  Sauté    │                                      |
|   │  Braise   │                                      |
|   └───────────┘                                      |
|                                                      |
+------------------------------------------------------+
```

布局、社区颜色、桥接节点全部由算法自动生成，不依赖手工编排。

## 6.7 复习模块

### 功能说明

复习模块帮助用户基于科学的遗忘曲线模型回顾卡片，确保长期记忆保留率，而不是简单按"熟悉度"线性排序。

### 设计动机

朴素做法（按熟悉度从低到高排序）存在根本缺陷：

- 用户每天反复看到同一批最不熟的词，已掌握的词永远不再露面，长期反而被遗忘；
- 没有"何时该复习"的时间判断，复习时机要么过早（浪费）要么过晚（已遗忘）；
- 不区分"难记的词"和"刚学的词"，调度策略一刀切。

因此本系统不采用熟悉度排序，而是为**每张卡片维护一条独立的遗忘曲线**，由算法精确预测每张卡的下一次最佳复习时间。

### 核心算法：FSRS-4.5 间隔重复算法

本系统实现 **Free Spaced Repetition Scheduler (FSRS-4.5)** 算法（Ye et al., 2023），该算法目前是 Anki 官方推荐的下一代调度器。核心思想：

为每张卡片维护三个参数：

| 参数 | 含义 |
|---|---|
| **D (Difficulty)** | 卡片的内在难度，反映用户对该概念的整体掌握难度 |
| **S (Stability)** | 记忆稳定性，表示记忆"半衰期"（单位：天） |
| **R (Retrievability)** | 当前可提取性，即此刻能回忆起来的概率 |

遗忘曲线模型：

```
R(t) = (1 + t / (9·S)) ^ (-1)
```

其中 t 为距上次复习的天数。每次用户对卡片做出反馈（Again / Hard / Good / Easy），算法：

1. 根据反馈和当前 D / S / R 更新 D 和 S；
2. 计算"R 衰减到目标保留率（如 0.9）"对应的天数 t\*；
3. 将 next_due = 今日 + t\* 写入数据库。

每日复习队列由 `WHERE next_due <= today` 直接查询得到，按 R 升序排列（越接近遗忘的越优先）。

### 主要功能

1. 基于 FSRS 调度的每日复习队列（不是熟悉度排序）；
2. 显示卡片正面：词条；
3. 点击显示背面：解释、用户笔记、来源图片；
4. 用户选择 "Again / Hard / Good / Easy" 四档反馈（对应 FSRS 标准输入）；
5. 系统根据反馈更新 D / S，并预测 next_due；
6. 支持按标签、类型、来源图片、**社区主题**（联动 6.6 知识图谱）筛选复习范围；
7. **复习统计页面**：展示个人遗忘曲线、长期记忆保留率、每日新词 vs 复习词比例。

### GUI 设计

```text
+------------------------------------------------------+
|  复习模式  ·  今日队列 12 张 · 已复习 3/12            |
+------------------------------------------------------+
|                                                      |
|                    Carbonara                         |
|                                                      |
|              点击查看解释                             |
|                                                      |

+------------------------------------------------------+

+------------------------------------------------------+
```

下方显示当前卡片的 S / R 状态，让用户感知"系统在做什么"，而不是黑箱排序。

### 数据库扩展

每张卡片新增字段：`difficulty FLOAT`、`stability FLOAT`、`last_review DATE`、`next_due DATE`、`review_count INT`、`lapses INT`。同时新增 `review_log` 表，记录每次复习的 (card_id, timestamp, rating, S_before, S_after) 用于后续参数优化与统计分析。

## 14. 项目难点分析

### 14.1 模型输出稳定性

视觉语言模型可能返回格式不稳定，因此需要：

- 明确 JSON Schema；
- 对返回结果做解析和校验；
- 缺字段时使用默认值；
- 解析失败时展示原始结果并允许用户手动编辑；
- 提供 Mock 模式保证展示稳定。

---

### 14.2 候选卡片与已有卡片的状态管理

系统需要区分：

- 新词；
- 已有词；
- 熟悉词；
- 相似词；
- 被忽略词。

这部分是核心工程复杂度之一，需要设计清楚的状态流转。

---

### 14.3 GUI 复杂度

系统包含多个复杂页面：

- 图片预览；
- 图片标注；
- 候选卡片列表；
- 卡片详情编辑；
- 图谱显示；
- 复习界面；
- 模型配置页面。

这要求较好的 Qt 信号槽设计和页面状态同步。

---

### 14.4 数据持久化

卡片、图片、关系、复习记录、模型配置都需要长期保存。需要保证：

- 数据不会丢失；
- 图片路径有效；
- 卡片和图片的关联正确；
- 删除卡片时关系同步删除；
- 导入导出格式稳定。

---

### 14.5 间隔重复算法实现

复习模块若仅按熟悉度排序则缺乏理论基础和长期效果。本项目自研实现 **FSRS-4.5 间隔重复算法**，需要正确处理：

- D / S / R 三参数的初始化与更新公式；
- 遗忘曲线 R(t) 的反函数求解（给定目标保留率反推下次复习时间）；
- 用户反馈四档（Again / Hard / Good / Easy）与参数更新的映射；
- review_log 数据持久化与个人化参数优化（可选 P3 功能）。

该算法是 Anki 官方在 2023 年后推荐的下一代调度器，理论基础来自记忆心理学的 DSR 模型，是本项目区别于"普通卡片软件"的关键技术骨干之一。

---

### 14.6 知识图谱算法实现

知识图谱模块的核心难点不在于关系存储，而在于"如何把数百到数千个节点 + 上千条关系组织成用户可读的可视化结构"。本项目自研实现两个经典图算法：

- **Fruchterman-Reingold 力导向布局**：需要正确处理斥力 / 吸引力的数值稳定性、温度衰减策略、收敛判定，以及在 QGraphicsScene 中以动画形式增量渲染；
- **Louvain 社区检测**：需要正确实现模块度增量计算、节点局部移动 → 社区合并的两阶段流程，以及在卡片增删时的增量更新（避免全图重算）。

这两个算法直接决定图谱页面的可用性，是本项目最具技术深度的模块之一。

---

## 15. 项目创新点

1. **图片作为知识库入口**
   用户不需要手动输入知识点，只需要上传图片。

2. **视觉语言模型直接生成结构化候选卡片**
   避免传统 OCR + 分词流程的复杂性和不稳定性。

3. **用户知识状态参与模型识别**
   系统会根据已有卡片和熟悉度过滤重复或低价值词条。

4. **人机协同的确认机制**
   模型负责推荐，用户负责确认和最终编辑。

5. **来源图片追踪**
   每个知识点都能回到原始图片语境。

6. **算法驱动的知识图谱可视化与组织**
   实现 Fruchterman-Reingold 力导向布局算法自动排布节点，结合 Louvain 模块度优化算法进行社区检测，自动识别用户知识库中的主题簇与桥接节点。布局、聚类、关键节点识别全部基于经典图算法自动完成，不依赖人工编排或外部图数据库服务。

7. **基于遗忘曲线的科学复习调度**
   实现 FSRS-4.5 间隔重复算法，为每张卡片维护 Difficulty / Stability / Retrievability 三参数遗忘模型，基于 R(t) = (1 + t/(9·S))⁻¹ 的可提取性曲线动态预测下次复习时间。相比朴素按熟悉度排序，能在更少复习次数下保证长期记忆保留率。

8. **知识图谱与复习闭环**
   卡片不只是静态笔记，还可以基于社区结构进行专题复习与学习路径推荐（社区主题 × FSRS 调度联动）。

9. **可自定义识别器**
   用户可以配置模型、Prompt 和场景模板，扩展不同使用场景。

## 19. 总结

本项目的核心不是简单调用视觉语言模型，而是围绕“图片中的陌生知识”建立一个完整的管理闭环：

```text
图片理解 → 候选卡片 → 用户确认 → 知识库 → 来源追踪 → 关系图谱 → 复习巩固
```

它的主要复杂度来自：

- 多页面 GUI 设计；
- 视觉语言模型接口抽象；
- 结构化 JSON 解析；
- 候选卡片状态管理；
- 卡片库增删改查；
- 来源图片和卡片的关联；
- 熟悉度与复习状态管理；
- 轻量知识图谱维护。

因此，它非常适合作为一个生活类、学习类、实用性强的程序设计实习项目。项目既有清晰的现实痛点，又有足够的工程复杂度和 GUI 展示空间，同时可以根据时间灵活裁剪功能范围。
